# L3-03 Durable analysis jobs and AI usage

Status: implemented and verified locally, 2026-09-12; [integrated evidence](verification/L3-03.md) retains human and external gates. The contract was recorded before runtime changes under continued implementation authorization. Dependencies: locally implemented L1-05 retries, L1-10 controls, L3-01 fit and L3-02 quality; their human/external gates stay open.

## Decision and scope

Keep the modular monolith, PostgreSQL candidate and existing DomainEventProcessor. Add grouped analysis intent and per-lead associations; one AnalysisRequested event per lead reuses existing stages, attempts, leases and fences. There is no second queue, scheduler phase, broker, external workflow authority or unrestricted AI loop.

New UI submits asynchronously. Legacy bulk and individual analysis-stage endpoints retain synchronous compatibility through the same persisted job/event path: enqueue, process the relevant events once, then return the existing result shape plus job identity. They do not wait/retry in an HTTP loop or run a separate untracked generator. Legacy omitted bulk selection inspects the first100 active directory records, processes at most50 eligible IDs and labels selection_scope=FIRST_100_ACTIVE_LEADS. The asynchronous endpoint is the primary operator flow; legacy callers can still experience request duration and must use job lookup after a lost response.

Freeze 1 to 50 explicit, distinct, active, workspace-owned lead IDs per job. At most 100 unfinished analysis items per workspace at admission. Empty/oversized/foreign/archived selections fail atomically before any job or model call. Explicit request_key idempotency binds the selected IDs, mode and target stage; identical replay returns the existing job, changed intent conflicts. Missing selection is not all leads on the new API.

Modes are ANALYSIS_ONLY and PREPARE_DRAFTS. Target stages are SNAPSHOT, SYNTHESIS, RECOMMENDATION and PLAN. The primary UI explicitly requests PLAN with PREPARE_DRAFTS, preserving the prior reviewed-draft workflow; draft creation does not approve or send. The internal execution_scope is PIPELINE or SINGLE_STAGE; public job requests cannot set it or simulation controls. Individual compatibility endpoints stop at their named stage and preserve existing precondition/error/failure-injection contracts where applicable. Test controls remain unavailable in production.

## Persistence and processing

analysis_jobs owns request identity/hash, actor, mode, target stage, internal execution scope, captured generation, bounded test-only simulation, revision, timestamps and cancellation/retry decisions. History allows at most100 decisions within64KiB; cancelling a job is terminal. Generic Event recovery excludes AnalysisRequested and cannot directly retry or close its events. analysis_job_items links a bounded ordinal and scoped lead to exactly one managed domain event. Existing event state, processing_fence, attempts, retry_deadline_at and stages own runtime progress; no duplicate lease authority.

Existing event defaults remain five total processing attempts, a 24-hour retry window and a 120-second lease. Every provider request remains bounded to 15 seconds. Each artifact, progress marker and reviewable draft action commits under the exact current event ownership and current source authority. Generation stays outside transactions. Retry reevaluates inputs and reuses only matching current READY artifacts, never blindly trusts a saved DONE stage. A shared READY artifact cannot be downgraded by another failed generation.

Capture the generation contract at enqueue. Changed deployed model/provider/prompt/schema/adapter or deterministic snapshot/recommendation/planner/business-fit contract holds old queued work as ANALYSIS_VERSION_CHANGED and requires a new explicit job. Source changes during generation discard late output under existing currentness guards; already incurred usage remains recorded. Existing evidence/freshness/contact/tenant policy remains authoritative. Restricted or archived leads cannot gain outbound work.

Cancel with expected_revision and a reason fences and dismisses unfinished events in one workspace transaction; completed artifacts and usage remain historical facts. Running provider work may finish, but its old event fence cannot publish or create a draft. Cancelled jobs do not reopen. Explicit retry affects only eligible held items with remaining original processing attempts/deadline, increments job revision and preserves spent provider counts. Admission holds are visible and do not spin automatically or silently cache a ready fallback. A fresh job is an explicit new request, still subject to workspace quotas.

## API and UI contract

POST /api/intelligence/jobs: {organization_id,request_key,lead_ids,mode,target_stage} ->202 {job,replayed}. GET /api/intelligence/jobs accepts organization_id, optional lead_id/request_key and bounded pagination; GET /api/intelligence/jobs/:id returns {job}. POST /api/intelligence/jobs/:id/cancel or /retry accepts organization_id,expected_revision,reason and returns {job}.

Job fields: id,organization_id,request_key,revision,mode,target_stage,requested_by,status,created_at,updated_at,cancelled_at,counts,can_cancel,can_retry,command_block_reason,items. States: QUEUED,RUNNING,RETRY_PENDING,COMPLETED,PARTIAL,FAILED,CANCELLED. Counts retain total/queued/running/retry_pending/completed/failed/cancelled. Items retain id,lead_id,lead_name,event_id,state,stage,attempts,max_attempts,next_attempt_at,retry_deadline_at,error_code,error_message,reused,stages and artifact references. Stage entries contain key,status,artifact_type,artifact_id. Read projection is metadata-only and bounded to at most 50 items per job, with at most 16 stage entries and history pages default10/max20; source/model payloads are not loaded for progress.

Intelligence jobs are deep-linkable by job ID. Lead detail shows active/latest work separately from CURRENT/OUTDATED. Dashboard uses the same submit flow. Polling and uncertain-submission recovery are GET-only; no automatic POST on focus/reload. Completion refetches current intelligence and cannot itself prove currentness. Explicit cancel/retry uses server capability and expected revision; drafts survive conflicts. Existing browser assertions for partial failure, currentness, reuse and lost responses remain meaningful under durable polling.

## AI invocation authority, usage and estimates

Only synthesis and reply classification currently call a model. Deterministic recommendation/planning, local rules, exact reuse and direct deterministic stop handling must not create phantom provider attempts. A local-hosted or free-named LLM still counts as a configured invocation.

Use an immutable per-invocation context/gateway, never mutable tenant state on the shared provider. Context binds workspace, lead, purpose, exact live domain-event or inbound-receipt origin/fence, input and request fingerprints, pipeline/prompt/schema versions and provider/requested model. Job linkage is resolved from stored origin, not trusted caller IDs. Validate request/options/size before admission. Admission and current-origin checks commit under the workspace gate before network I/O. Same invocation_key cannot grant a second I/O permit.

AiInvocationService.admit(context) returns an attempt identity and one authorization token, or a typed visible hold without a provider call. AiInvocationService.observe records bounded telemetry idempotently against immutable attempt authority; it deliberately accepts truthful late observation after job cancellation/lease loss without publishing an artifact. Raw prompts, replies, provider bodies, credentials/endpoints and raw errors are never stored in the ledger.

workspace_ai_controls owns revisioned owner pause, provisional daily admission limit100 and logical in-flight limit2, monotonic budget clock, optional exact pricing and audit history. Allowed limits are bounded; changing controls/retrying never refunds spent admissions. Every admitted call consumes its captured UTC day's count permanently, including rejection, invalid output, timeout, crash and cancellation. Expiry may release a logical concurrency slot but does not assert that remote provider work stopped or refund the day. Clock observations survive a held admission so rollback cannot reopen earlier quota days.

Provider metadata is observed before parsing completion text or validating domain output. Persist requested/returned model, bounded response reference, validated provider input/output/total token counts, CLIENT_OBSERVED elapsed time and outcome. Missing/malformed usage is null/UNKNOWN, not zero; zero requires an explicit valid report. Budget denial propagates from synthesis as a held stage rather than a cacheable ready fallback. Reply admission denial preserves mandatory opt-out handling and becomes explicit UNKNOWN/review with a bounded reason.

Optional owner pricing is scoped to the requested provider/model and captures exact decimal USD rates per million input/output tokens, at most six fractional digits, plus revision. Estimates use exact integer micro-USD arithmetic and reported token counts, rounding the combined input/output amount upward once per attempt to the next micro-dollar; rates are never fetched or invented. Unconfigured or unusable usage yields unknown cost. An estimate is not a provider invoice, hard monetary budget or independently measured charge. Totals show estimated subtotal and unknown-count/coverage separately. No call count, free model label or local endpoint implies zero cost.

GET /api/ai/usage provides a bounded current UTC-day summary and paged attempt metadata. GET /api/ai/controls and owner PUT /api/ai/controls expose current revision, limits, optional pricing, effective holds and recorded history; updates require expected_revision and reason. Current controls/history responses and usage summary/cursors are implemented in the shared UI/API types. Controls history defaults20/max50; usage attempts default25/max50. Pagination rejects noncanonical integer queries.

Synthesis reuse must include a shared immutable generation descriptor across app, transaction-scoped current readers and event-stage builders. A model/prompt change cannot reuse another engine's READY output or make every scoped reader accidentally compare against the default local engine. The provider adapter returns completion value separately from telemetry; existing strict model result schemas remain unchanged.
