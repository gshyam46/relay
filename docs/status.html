01

Production foundation

Complete

The database layer, configuration, and observability a real deployment needs. The DatabaseClient contract became asynchronous — it had to, because node:sqlite is synchronous and every PostgreSQL driver is not.

  • ✓PostgreSQL/Supabase adapter behind the same contract as SQLite. Setting DATABASE_URL is the entire switch.
  • ✓Async contract rolled through 19 repositories, all services, the worker and the API.
  • ✓One SQL dialect: ? → $n translation, BIGINT/NUMERIC coerced to numbers, engine-specific date SQL removed.
  • ✓Versioned migrations with schema_migrations, each applied transactionally. Existing dev databases adopt the runner without a rebuild.
  • ✓Environment/secrets configuration in one module, with boot-time validation that refuses SQLite in production.
  • ✓Structured JSON logging with per-request ids; error taxonomy with status + code + expected/defect.
  • ✓Liveness and readiness endpoints, graceful SIGTERM shutdown, worker overlap guard.
  • ✓All 176 runnable tests green against the abstraction; full browser cycle verified end to end.
  • ✓Verified against real PostgreSQL 18.1. The gap flagged in the first report is closed: the machine turned out to have PostgreSQL installed, so a throwaway cluster was spun up on port 55432 and the entire suite — all 180 tests, not just the 4 adapter ones — was run against it.

Fixed in Phase 1

WhereWhat
shared/http.jsAny error's message was returned to the client verbatim, including unhandled defects — that would have leaked SQL fragments in production. 5xx now returns a generic message plus a request id.
api/app.jsX-Forwarded-Proto was trusted unconditionally for the cookie Secure flag, so a direct client could claim HTTPS. Now gated on TRUST_PROXY.
server.jsThe worker interval had no overlap guard — with awaited network round trips a slow tick could execute the same action twice.
outbound.tsxclient:build was broken on the branch (unused variable under tsc -b), so the served frontend could not be rebuilt.
scripts/smoke-api.jsnpm run smoke still called POST /api/organizations, removed when session auth landed — it had been failing with a 401 instead of checking anything. Now registers and carries a session.
.github/workflowsCI ran one engine and never built the client, which is how a broken client:build and untested PostgreSQL SQL could both sit on the branch unnoticed. Now three jobs: SQLite, PostgreSQL, client build.
postgres-adapter.test.jsData-loss footgun. The adapter tests ran DROP SCHEMA public CASCADE. The documented workflow is to run them against the configured DATABASE_URL — which would have destroyed the staging database. Every test now works inside its own generated schema and touches nothing else.
test toolingThe test harness read TEST_DATABASE_SSL while the app reads DATABASE_SSL — two names for one concept, so a single .env silently half-worked. Now one falls back to the other.
