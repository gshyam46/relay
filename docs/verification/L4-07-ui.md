## Implemented scope

The public landing presents **AI Lead Intelligence & Outbound Automation**, a deterministic three-enquiry example, evidence drilldown, an unknown budget, distinct business fit and contact restrictions, editable exact-revision review, simulated replies, a persistent stop branch and explicitly human-recorded sample outcomes. Switching enquiries and resetting clear dependent example state. The example does not call domain or provider APIs. The fixed September 2026 sample dates are illustrative, not live freshness assessments.

The public `/` page works without authentication or an API response. The demo loads on explicit activation and has a readable fallback if its chunk fails. The native CSS/SVG illustration needs no image service, remote font or new dependency. The real `/register` Sandbox workspace CTA and protected deep-link sign-in path were exercised. Parent-owned routing preserves existing protected paths and uses `/app` for the dashboard, as recorded in [the completion contract](../COMPLETION_PLAN.md).

The pilot-interest form uses the real parent-owned endpoint. It requires explicit storage consent, distinguishes a saved request from an accepted pilot, retains editable entries after a definitive rejection, and retries the identical command after an uncertain result. It records interest separately from customer leads and makes no email, booking, notification or live-channel promise. The request exists only in memory on the page until accepted; browser storage is not used for this form.

Owned files are the `client/src/marketing/` components, fixtures and scoped stylesheet; `scripts/helpers/landingFixture.js`; `scripts/verify-landing-ui.js`; and this evidence. API, migration, public metadata, route composition and the tracked launcher remain the integrating owner's scope.
