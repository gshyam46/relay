# L1-02 - Tenant and simulation boundaries

Product: **AI Lead Intelligence & Outbound Automation**.
Date: 2026-09-11.
Status: implementation and local automated evidence complete; human/browser and real PostgreSQL acceptance pending.

## Completed

- Both synthetic callback routes require authenticated action ownership. The callback service itself now requires organization_id; internal worker and token-scoped provider callers supply it explicitly.
- A callback event ID already belonging to another action/workspace returns a generic conflict without exposing the stored receipt. The current global unique key remains; provider-scoped receipt identity and durable replay remain L1-07.
- The HTTP worker scopes both pending events and executable actions to the session workspace. Internal server workers can still intentionally process all workspaces.
- Synthetic callback/inbound, worker and due-run routes default off. Explicit ENABLE_TEST_CONTROLS=true works only in test/development; staging/production reject those routes before authentication/body processing. Authenticated simulate_* and mock_behavior inputs are also refused when controls are disabled.
- HTTP writes, settings access and approval lookup require OWNER, the only current supported command role. Additional role/membership behavior remains L5-02. Sessions with differing user/workspace ownership fail authentication.
- Single, edited and bulk approval/rejection derive reviewer_name from the session and persist stable reviewer_user_id in audit metadata. Legacy reviewer_name type validation remains; its supplied value cannot impersonate another actor.
- Sequence enrollment validates every selected lead before creating any run. A mixed foreign/missing selection leaves all existing runs unchanged.
- GET /api/auth/me reports capabilities.test_controls. React simulation controls and instructions require the server capability and owner role, defaulting off while unknown. Login/register refresh the capability.
- The isolated E2E health capability requires test mode, memory SQLite, explicit controls and no configured provider environment. That harness refuses nonsandbox channel provider settings; ordinary application servers do not advertise the marker.
- Background mock delivery/human-task completion simulation runs only with explicit local test controls. Real human-task completion remains a separate L4 product requirement.
