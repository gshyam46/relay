Date: 2026-09-12. Product: **AI Lead Intelligence & Outbound Automation**.
Scope: the [recorded freshness contract](../L2-05_FRESHNESS.md). This is local automated browser evidence and engineer inspection with synthetic records. It does not establish target-operator acceptance, real PostgreSQL behavior, provider delivery or predictive scoring quality.

## Implemented operator journey

The Intelligence list separates never analysed, current and outdated analysis from readiness/recommendation processing stages. It offers currentness filters, text search, last-analysis time, state reasons and explicit analysis selection. Selection is bounded to 1000 IDs; each request processes at most 50. The page shows hidden selected counts and retains failed or unprocessed IDs while clearing only completed results. Results distinguish newly completed work, reused unchanged results, failures and records not processed. Per-record failures retain a human name even when a concurrently archived record disappears from the active directory. The Dashboard's existing bulk action uses the same truthful result totals.

Lead detail adds currentness, last analysed/checked time, the next recorded source transition, compared business/enquiry/contact revisions and links to review changed context. The six source-assessment cards keep value state, assertion and observation freshness separate. Conflicting alternatives never become a selected fact. Stale, undated, inferred and future-at-recording observations remain visibly limited. Historical dates remain historical; a usable historical fact with no observation time still discloses that missing time. Saved research assessments are available in a separate expandable list with recorded source references. Current analysis is not a claim that source facts were reconfirmed, that the lead fits the business or that contact is permitted.

GET queries recheck currentness on focus and while the view is visible. The interval uses the server's assessed/next-check times, capped by a 30-second periodic check; browser wall time does not establish authority. These checks never POST analysis. Refresh is an explicit request against saved inputs. Unchanged results are reused, and observation dates are not rewritten. A failed currentness read marks cached information uncertain and disables refresh until a successful check. An unconfirmed POST response triggers saved-state invalidation without an automatic second POST. Archived detail retains source/history visibility and disables refresh.

Recommendation comparison shows the current recommendation, when available, beside the prior completed historical recommendation, with timestamps, recorded input revisions and input differences. Missing historical details remain explicitly unavailable. It reports whether recorded step/reason changed without claiming that a particular input caused a model decision. An outdated prior recommendation is never presented as the current recommendation.

The focused browser fixture uncovered an existing evidence-label crash: metadata review evidence legitimately has a null claim field. The consumer type now preserves that null and the detail renders it as Source review, retaining the record and optional recorded title. The same mixed-source fixture now exercises that regression successfully.

## Remaining acceptance and limits

Target-operator QA remains open: explain the difference between current analysis and a current customer assertion; identify and correct a conflicting or aged fact from its source/history; understand a recommendation comparison without inferring unsupported causality; refresh only when needed; and recover a failed or unconfirmed request without assuming it was undone. Confirm the provisional observation policy against the pilot business's actual sales cycle before treating it as customer validated.

Exercise keyboard and screen-reader navigation, focus rechecking, large research sets, long multilingual source references, zoom and mobile layout. The broader application's navigation/accessibility and bundle-size work remain open. Selection is local component state and does not survive navigation away or reload; no durable analysis queue or automatic refresh job is introduced. Server processing caps and incomplete/failed outcomes must remain explicit as scale grows. Exact contact permission and outbound approval/dispatch are separate authority checks, including when the analysis badge reads current. Real PostgreSQL, operator acceptance, model-quality and live-provider gates remain separate from this local automated result.
