# L3-04 audited feedback and evaluation UI evidence

Date: 2026-09-12. Scope: production React under the [feedback and evaluation contract](../L3-04_FEEDBACK_EVALUATION.md). These are automated local checks with synthetic records, not customer acceptance, independently adjudicated labels, model accuracy or production release approval.

## Implemented workflow

Owner review launchers open exact saved SNAPSHOT, SYNTHESIS, RECOMMENDATION, PLAN and inbound REPLY targets. The snapshot target includes its fit assessment as a whole. The lead history also exposes saved snapshot review. Opening and refreshing a panel is read-only. An open draft retains its original artifact identity when newer analysis becomes current.

Correctness and usefulness require explicit judgments. Unclear correctness and unassessed usefulness remain available. Each record or withdrawal requires a reason and appends immutable review history with actor, revision and time. Feedback never rewrites a source, prediction, contact restriction, approval or task. Source correction stays a separate link to the existing lead workflow.

Feedback request keys and exact pending commands survive reload in workspace/target-scoped session storage. GET lookup can confirm an accepted request before a late POST failure without restoring uncertainty or submitting another request. Conflicts retain the judgments and reason until an explicit latest-revision review. After a successful write, the token advances only when GET confirms that same accepted revision; a newer concurrent revision is not silently adopted.

Reply feedback defaults to operational-only, excluded from evaluation. Synthetic and permission-reviewed nomination are explicit owner attestations, separate from dataset inclusion and independently verified permission. Missing original input cannot be nominated using application summary text instead. A disputed opt-out remains restricted.

The separate Reviewed reply evaluation view requires an explicit selection of exact feedback revisions, a name and a DEV or HOLDOUT split. Selection is capped at100 with bounded candidate pages; hidden selections are counted. Dataset versions are immutable. Creation has exact request-key recovery; rejected inputs retain the draft and selection for correction. The UI uses the server's120-character name bound and actual EVALUATION_REQUEST_INVALID rejection code.

Explicit replay compares recorded operational categories with captured local-rule output against owner labels. Results expose counts, abstentions, opt-out errors, per-class denominators and unknown ratios. Historical columns say Captured local rules because a stored result does not establish that its code is still the current deployment. Dataset APIs expose aggregate results and version/source manifests, not original text, member identities or per-case predictions. Changed/withdrawn labels make earlier results historical. A new version cannot reset consumed holdout groups; the original dataset and same captured candidate can still return its exact saved result.

## Remaining acceptance

Customer/native-language reviewers must validate the usefulness and correctness of labels, nomination permission, independent cohort selection and whether the distinction between feedback, source correction, dataset inclusion and contact permission is understood. Original reply text remains available in the existing conversation surface; historical method and source limitations remain explicit. Mobile, screen reader, keyboard,200% zoom, long review histories, larger candidate selections and protected-group explanations require human QA. Owner-only permission/tenant, transaction, dataset and engineering-gate results are recorded separately by the integration/backend owners.

No test here establishes hosted-model quality, calibrated confidence, independent holdout quality, customer generalization, real PostgreSQL behavior, processing permission or release authorization. Provider calls in the local replay are zero by contract. Business outcomes, inbox resolution, full composition and customer pilot evidence remain their later roadmap work.
