# L3-03 analysis jobs and AI usage UI evidence

Date: 2026-09-12. Scope: production React with the recorded [analysis job contract](../L3-03_ANALYSIS_JOBS.md). This is automated local browser evidence, not operator acceptance, production-worker validation, real model quality, provider billing or PostgreSQL certification.

## Implemented operator flow

Dashboard, Intelligence and lead detail explicitly submit a persisted PLAN/PREPARE_DRAFTS job. Each submission binds 1–50 explicit lead IDs and a request key. Larger staged selections expose the first-50 action; completed IDs clear while failed and unprocessed selections remain. Progress and recent-job history read persisted server state. Opening, focusing, reloading and polling a page do not enqueue work.

The browser retains an uncertain request key in workspace-scoped session storage. An accepted but lost response is recovered by GET lookup; an explicit retry sends the same key and intent. A definitive rejected selection can be corrected explicitly. Job cancellation/retry use the saved revision and a required reason. HTTP errors and concurrent decisions preserve the reason and expose a current-state review action. Completion refetches currentness rather than claiming that completed work is necessarily current. Changing the displayed lead cannot attach the previous lead's submitted job to its record.

Settings exposes owner pause, daily admission and logical in-flight limits, revision history, optional exact USD rates, current UTC-day usage and bounded invocation history. Unknown tokens/cost remain unknown. Estimates retain their pricing revision and captured pipeline/prompt/schema versions; they are neither invoices nor hard monetary limits. Cancelling work or changing limits does not refund admissions.
