# L1-07 integrated webhook receipt and replay verification

Product: **AI Lead Intelligence & Outbound Automation**.
Date: **2026-09-11**.
Status: local implementation and automated verification complete for this bounded slice; **L1 remains in progress**. No deployment, customer database migration or real provider send was performed.

## Completed and scope

The [contract](../L1-07_WEBHOOK_REPLAY.md) was recorded before dependent implementation and follows ADR-007 on the existing modular monolith, PostgreSQL direction and workspace transaction gate.

- Migration 0006 adds durable immutable webhook receipts, processing budgets/leases/fences, callback/inbound completion cursors and append-only owner reviews. Migrations 0001-0005 remain unchanged by this slice. Historical projections retain LEGACY_UNKNOWN; no old receipt, completion or send authority is invented.
- Current SendGrid Event Webhook/Inbound Parse and internal callback/inbound paths persist normalized input before acknowledgement. HTTP success means durable receipt; processing can still be waiting or quarantined. A receipt storage failure returns a retryable failure; an event batch is fully stored before any item is processed.
- A normal worker resumes due or abandoned local processing. Each receipt has five attempts and a 24-hour deadline from first claim, a 60-second fenced lease, and persisted exponential retry timing with jitter. Replay never calls an outbound provider.
- Callback delivery facts and the PENDING effects cursor commit together. Original immutable conversation content, appropriate no-response task and DONE marker commit together in a later transaction. Failure preserves delivery evidence and remains repairable. Follow-up timing uses the original execution completion plus 48 hours; later replies, restrictions or stopped workflows prevent obsolete work.
- Inbound classification and canonical identity are persisted once with lead provenance and mandatory contact restrictions. Message, status, task changes, reply event and DONE marker then commit together. Duplicate/restarted processing reuses the original interpretation and cannot repeat effects.
- Deterministic intelligence snapshots refresh from persisted reply events through the worker, including the opt-out signal. Restricted leads skip new synthesis/contact recommendation/planning. General failed domain-event retry remains L1-06.
- Pending mandatory policy conservatively pauses sending across its workspace without consuming attempts, changing approval or permanently blocking unrelated actions. Actual restrictions retain priority. Changed-content conflicts preserve the original receipt and run only valid contact-policy effects against separate retained evidence.
- The owner Event recovery page exposes a paginated queue, bounded original preview, retry timing, policy state and review history. RETRY/CLOSE decisions require the displayed fence and session actor with evidence. They cannot edit original input, reset limits, reopen completed history or waive unfinished restrictions.
- A bounded worker cleanup purges normalized bodies of processed/closed receipts after 30 days while retaining identity/hash/history for duplicate detection. Unresolved bodies remain. Inbox processing participates in shutdown drain before database close.

This covers the current ingress adapters and local processing contracts. It does not implement full scheduling, general thread/assignment/reply composition, other providers, automatic repair of ambiguous historical records, or production certification.

HTTP additions: GET /api/webhook-receipts, GET /api/webhook-receipts/:id, POST /api/webhook-receipts/:id/review. All are owner-scoped. List accepts state, limit and offset; review accepts expected_fence, decision RETRY/CLOSE and evidence_note. Workspace and actor come from the authenticated session.

Provider acknowledgements include receipt identity and processing state. SendGrid event batches return per-item outcomes after durable storage; Parse returns 202 after durable receipt. A later policy/storage processing failure is represented by the persisted retry state. Unauthenticated requests and invalid outer request bodies remain errors.

Receipt identity hashes the tenant, provider, logical connection, ingress family and provider event ID; input hash covers immutable normalized content/correlation. New callback projection storage IDs derive from the receipt. Callback detail preserves the original provider-facing event ID separately from its storage key. Receipt JSON is bounded to 256 KiB; normalized Parse text is bounded to 32,768 code units, with oversized or ambiguous identity retained for review.

Independent review found and corrected these concrete gaps during integration:

1. Changed-content opt-outs could lose their required suppression. Conflicts now have separate policy-only processing; injected storage failure keeps them pending and later recovery applies the actual recipient restriction without domain projections.
2. A failed handler whose lease had expired could quarantine abandoned work. Failure persistence now requires live ownership, leaving the receipt recoverable by a new claim.
3. A durable-but-unapplied opt-out could be acknowledged while sends continued. Pending mandatory policy now defers workspace sends and relevant task effects without consuming dispatch attempts.
4. Duplicate Parse form fields could silently overwrite identity. Ambiguity is preserved, with no arbitrary sender/lead selection.
5. Harmless missing-reference events and inspected legacy projections could unnecessarily hold policy forever. Positive determination of no policy or valid policy-only completion now permits review closure without replaying unknown history.
6. Moving snapshot refresh to the worker initially skipped opt-out intelligence. A pre-existing snapshot now refreshes with the opt-out signal before contact recommendation stages are skipped.

Previous tests were updated for the explicit asynchronous contract: they prove stale snapshots are hidden until the persisted reply event is processed, then preserve signal/version/cache/idempotency assertions. The failed-suppression HTTP test now proves durable acknowledgement plus held dispatch and normal worker recovery; a separate injected receipt-storage failure still requires HTTP 503. No failed assertion was removed to conceal a regression.

## Known issues and external gates

- **Real PostgreSQL remains unverified.** The current check found no explicit disposable test target/opt-in or .env; psql/postgres commands were unavailable, and Docker could not connect to its local engine pipe. All 16 gated tests are skipped, not passing evidence. PostgreSQL multi-process ordering, restricted roles, populated upgrades and restore need an isolated target.
- **Live provider acceptance remains unverified.** Signed provider redelivery, real mailbox delivery/reply routing and actual received-copy checks remain required. Local intercepted HTTP fixtures do not certify SendGrid.
- **Some unresolved policy evidence needs operator remediation.** A permanently invalid or foreign-reference policy event remains quarantined and pauses workspace sending. Ordinary retry cannot correct immutable identity or replenish exhausted budgets; closure cannot discard pending restrictions. An inspected, auditable remediation procedure/workflow is a pre-customer gate. No bypass is offered.
- Legacy callbacks/inbound rows without linked completion history remain reviewable history; the migration does not safely infer missing effects. Closure records a decision, not successful processing or delivery.
- Full domain-event retry, sequence scheduling, tenant fairness, quotas/kill switch, account recovery, shared manual/reply composer and the complete operator journey remain open.
- Parse attachments/raw MIME and general thread/assignment workflows are outside this slice. Retention covers terminal normalized receipt bodies, not the entire workspace data inventory or deletion policy.
- Browser, keyboard, screen-reader, mobile and human QA are pending. No browser automation runner was available/configured for this slice. Client route splitting/performance remains needed.
- The requested interactive landing page remains planned in L4-07/L5-07. No landing implementation or customer/public launch is claimed here.

## Human QA required

1. On an isolated staging build, inspect a failed callback whose delivery fact already committed. Repair the underlying local failure, retry and confirm exactly one original conversation message and appropriate task with the original due time.
2. Deliver a reply or opt-out before replay. Verify obsolete no-response work is absent, human response work is preserved where appropriate, and contact restrictions remain authoritative.
3. Reproduce received-but-pending policy, including failure then recovery. Observe workspace sends waiting without new attempts or lost approval. Inspect the explicit hold when invalid evidence cannot complete; rehearse operator escalation before enabling customer traffic.
4. Inspect missing/foreign correlation, conflicting content and legacy records. Close only cases whose required policy completed; verify closure does not assert delivery, clear suppression or create a send.
5. Exercise owner/viewer/foreign-workspace access, duplicate and stale review submissions, pagination with more than 25 records, refresh/errors and unchanged original input.
6. Verify keyboard focus, Escape/close, loading and failure announcements, mobile layout, bounded content preview and understandable delivery-versus-processing wording.
7. With PostgreSQL and the chosen host, interrupt after receipt, core and final-effects commits; restart and demonstrate one correct result. Validate leases, graceful shutdown, upgrade/restore and terminal body retention.
8. Use controlled mailboxes for real signed provider batch/Parse redelivery, opt-out and copy checks. Record actual provider evidence separately from synthetic tests.
