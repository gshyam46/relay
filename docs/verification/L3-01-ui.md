## Implemented owner and operator journey

Settings has a deep-linked Fit criteria section using the existing business-profile revision. The owner explicitly enables rules and chooses required or preferred interest, location, budget and timeline criteria. No rule is preselected. Interest uses whole-value accepted/excluded aliases; location uses actual country plus explicit locality aliases or an explicitly selected whole country. Budget remains an exact decimal string in a chosen currency; timeline uses inclusive absolute dates. The editor explains unsupported paraphrases, ambiguous ranges, missing countries and the absence of currency conversion. It requires at least one required rule, records a change reason and preserves revision history. Explicit disabling saves null without removing previous criteria history.

Descriptive profile words are never parsed into executable rules. Required/exclusion notes remain manual-review requirements; preferred notes remain unassessed. Descriptive-profile saves omit fit_criteria so the server preserves active rules. Criteria saves carry the exact profile captured with their shared revision. A concurrent edit causes the same stale-revision protection as context changes: the draft and reason remain, and replacing them requires explicit reload. Profile history now also displays the criteria recorded in that revision.

Lead detail separates configured business fit, attention priority, source assessment, data readiness and contact-policy review. Each criterion shows its configured rule, result, reason, exact recorded value/provenance and freshness. Conflicting alternatives remain visible without selecting a winner. A review link opens and focuses the specific Enquiry field; a sourced correction invalidates the former fit until explicit refresh. The existing readiness-based recommendation score is retained under a separate Legacy processing attention disclosure with its recorded explanation; it is not presented as business fit. A known lead-level opt-out/suppression remains explicit, and every fit view links to the separate contact-policy/outbound review. No absence-of-restriction claim is inferred from fit.

The Intelligence list displays compact current fit and attention summaries, criterion review fields and separate currentness/processing stages. Business-fit and currentness filters make matching, review, nonmatching, unconfigured and unassessed records accessible. Server ordering uses configured fit and confirmed preferences within the returned page. The interface states that it is not a workspace-wide top list. Next/previous controls use the server's stable-ID cursor with at most 100 records per page. Explicit analysis selection survives page changes, shows hidden counts and retains the existing 1000-ID selection/50-record request boundaries. Search and filters apply to the returned page. A summary error does not fabricate an empty successful ranking.

Assessment coverage incomplete includes unresolved required criteria as well as unknown preferences. The final copy says that some criteria or preferences need review and that unknown values are not failed criteria. Saving or reading criteria does not automatically analyse, approve or contact anyone. Currentness, exact outbound review and dispatch remain separate server authority checks.

## Remaining acceptance and limits

Target owners must verify that explicit aliases, exclusions, geography, currency threshold and date windows match their actual business decisions. They must review unknown-language burden, ambiguous requests and missed lower-ranked opportunities on representative consented data. The finite rule implementation does not establish general semantic understanding or validate the proposed pilot priority-usefulness target. Independent versioned qualification/ranking fixtures and comparisons with recency/readiness baselines belong to the L3 evaluation gate; browser assertions are not a substitute for customer labels.

Ranking and filters apply to each returned page, not globally across a large workspace. Selection is component state and does not survive leaving the page or reloading. There is no durable analysis job queue, automatic contact, semantic criteria parser, FX conversion or runtime relative-date urgency in this slice. Keyboard/screen-reader coverage, 200% zoom, narrow screens, large multilingual lists and first-time operator comprehension remain required human QA. The focused field-link assertion demonstrates one keyboard focus behavior, not accessibility certification. Real PostgreSQL, provider and pilot/operator gates remain open.
