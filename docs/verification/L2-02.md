## Contracts changed

- Inspect returns indexed columns and sample cells without creating a batch or leads. Explicit mapped preview creates a reviewed version-2 batch without committing leads. Raw positional cells survive duplicate/blank/reserved headers.
- Date, currency, phone and assertion interpretation are explicit. Existing exact-money/date/unknown validation is reused; upload time cannot become enquiry or source time.
- Reviewed rows can be corrected before selection freezes; original raw cells and correction reasons/history remain. Stale revisions reject.
- First commit freezes selection/review revision. Bounded calls process at most 25 complete database-only row transactions. Resume reads persisted progress and does not replay committed lead/event effects.
- Duplicate candidates are ineligible in reviewed mode. Matches appearing after review become visible durable HELD outcomes; source remains for L2-03. No merge, existing-lead update or suppression removal occurs.
- IMPORT_ROW provenance binds the exact owned reviewed row/fact/resulting lead. A changed fact must carry a manual correction; prior imported source remains in history.
- New compatibility requests without mapping retain contact-only version-1 semantics while using bounded transactional safety. Historical unfinished version-0 batches require review; completed historical records stay readable.
- Migration 0010 is additive; no historic migration is edited and no ambiguous old row/event state is inferred. Its only data backfill is the bounded derived name/company hash used for consistent candidate matching; original lead/source fields and restrictions are preserved.

## Known issues

- PostgreSQL concurrency, scoped constraints, upgrade/restore and deployed roles require a dedicated disposable real PostgreSQL run.
- Browser automation with synthetic fixtures does not establish target-customer usability or full mobile/screen-reader/accessibility acceptance.
- Duplicate/shared-contact/repeated-enquiry resolution remains L2-03; held import rows retain evidence but cannot be resolved into existing or separate enquiries by this slice.
- Imports support the documented CSV size/row/column/cell limits, selected phone regions, date formats and currencies. No spreadsheet date serial, currency grouping inference or arbitrary country-specific phone parsing is promised.
- CSV source truth remains unverified. Imported values do not grant consent or prove buying intent/business fit.
- Automatic background import processing is not introduced. After interruption the operator resumes the saved frozen selection.
- Existing application-shell/bundle, large-workspace pagination/load and account/provider/customer gates remain later work.
- The modern interactive landing page remains planned in L4-07/L5-07; publication remains separately gated.

## Human QA

Required and not completed by implementation:

1. A target operator uploads a representative file, understands ignored/duplicate columns, chooses country/date/currency interpretation and explains the normalized values.
2. They correct an invalid row, inspect original source/history, choose only intended rows and recognize why duplicates are held.
3. They import more than one chunk, interrupt/refresh/relogin, resume the same batch and reconcile created/held/remaining counts without duplicate leads.
4. They inspect imported enquiry provenance, make a manual correction, refresh intelligence and review affected copy against the corrected facts.
5. Verify keyboard/screen reader/mobile/zoom, long multilingual data, stale sessions and actionable errors; separately perform PostgreSQL and provider/customer launch gates.
