# L2-02 React reviewed import verification

Date: 2026-09-12. Product: **AI Lead Intelligence & Outbound Automation**.
Scope: local implementation of the [reviewed CSV contract](../L2-02_REVIEWED_IMPORT.md). This records automated browser checks and engineer visual inspection using synthetic data. Customer/operator acceptance, live PostgreSQL and provider evidence remain separate gates.

## Completed

The Leads Import entry and Imports navigation open a dedicated upload, mapping, preview and saved-history journey. Inspecting a file creates neither a batch nor a lead. UTF-8 and bounded file input are checked before upload; column mapping uses stable indexes so repeated or blank labels do not overwrite source cells. Suggested mappings need review. Phone region, date format and default-currency interpretation require explicit choices, and changing interpretation clears its review checkbox. The source assertion is visible and defaults to operator-observed, as specified in the contract.

Preview shows normalized identity, eligibility, row errors, duplicate warnings, typed enquiry and unchanged raw cells. Operators explicitly select eligible rows; preview does not select or commit automatically. Row filters and pages keep the bounded file manageable. Row corrections require a reason, use the reviewed revision, preserve raw source and appear in before/after history. Saving a correction clears the selection for review. Stale corrections retain their draft and require an explicit discard/load action.

Import freezes the reviewed selection and requests at most 25 unfinished rows per step. Saved progress distinguishes imported, held and remaining rows. A lost response triggers a read of persisted progress and requires explicit resume; the UI does not automatically retry an uncertain request. Stopping or leaving the page stops further requests while an admitted step can still finish. Refresh, saved history and deep links reopen the same selection for resumption. History labels its newest-100 limit when truncated and uses row-derived committed progress. Legacy/compatibility imports remain inspectable with no commit controls in this reviewed UI.

Initial duplicates are ineligible and remain visible for the later reviewed-identity task. Newly detected duplicates after preview finish as held without creating a lead. Import does not grant contact permission. Completed selection and all source rows are distinct counts.

Imported enquiry facts show the actual CSV source link and exact decimal amount. Unchanged imported facts stay locked and retain their exact IMPORT_ROW provenance during unrelated edits. Correct this imported fact explicitly switches that fact to MANUAL, removes import identifiers and requires the operator's new source. Earlier imported values remain visible in enquiry history.

## Known limits and human QA

This explicit locally installed Playwright package is not a new dependency-locked portable CI browser environment. Desktop engineer inspection does not establish full accessibility or mobile/browser coverage. Application-shell mobile navigation and the existing initial bundle size remain broader product work.

Required operator acceptance remains open: use a representative customer CSV, interpret dates/currency/phone/assertion, recognize raw versus corrected values, select a subset, understand duplicate holds, recover after interruption, trace an imported enquiry and make a manual correction. Test keyboard/screen-reader, zoom, mobile, long multilingual values and multiple active reviewers. Live disposable PostgreSQL concurrency, migration upgrade/restore and pilot evidence remain separate.

Reviewed duplicate resolution, merge/separate decisions, full history pagination, exports and wider data UI remain L2-03/L2-04. Passing this bounded UI verification does not close those tasks or certify launch readiness.
