These records now participate in current intelligence and exact message review. The modular monolith, PostgreSQL/Supabase direction, contact policy and replaceable providers remain. No deployment, new package dependency, live provider send or customer database mutation occurred.

## Contracts changed

- Owner PUT and authenticated GET /api/business-profile and /api/leads/:id/enquiry-context, plus bounded GET /history. Updates carry expected_revision, reason and the full profile/enquiry snapshot. Workspace/actor come from the session and the current database owner row; foreign IDs and forged command fields reject. Stale saves return 409; identical normalized content at the current revision returns the existing row without another audit.
- Additive 0009 stores profile/enquiry revision snapshots with scoped actor/lead foreign keys, bounded revisions/JSON bytes and no legacy backfill. Highest revision is current; there is no extra mutable head or mass rewrite. Append-only is the application API contract, not a database UPDATE/DELETE trigger.
- Facts distinguish UNKNOWN, KNOWN and CONFLICTED. Provenance labels CUSTOMER_STATED, OPERATOR_OBSERVED and INFERRED remain explicit and unverified. Dates are not invented from capture/import time. Supported monetary currencies/scales use decimal-string input and canonical integer minor-unit strings, including values beyond JavaScript's safe integer range. Zero differs from unknown.
- Persisted profile/enquiry revisions enter snapshot fingerprints and cascade into current synthesis/recommendation/plan checks. Zero/zero preserves old no-context fingerprints. Known non-inferred facts become bounded quoted evidence with their actual source/revision/date and MEDIUM confidence. Conflict/inference or a combined value beyond the 500-character grounding bound requires review; the complete source value remains in enquiry history.
- Deterministic snapshot work serializes with context saves without model I/O. Direct model output finalizes in a short workspace transaction after checking original/current revisions; staged workers reuse their existing fenced gate. Supersession and audit are atomic with publication.
- Prepared review reads persisted revisions in the same workspace transaction as decisions/dispatch. An old approved revision cannot spend an attempt after context changes. New preview preserves existing human copy for renewed review; it does not claim regeneration. Already-authorized work and original retry limits/history remain.
- Action creation checks the current plan under the workspace transaction, with scoped action/audit/approval composition. Summary/attention read current fingerprints rather than treating historical READY rows as current. History remains inspectable.

## Known issues

- No dedicated disposable real PostgreSQL run occurred. Scoped FKs, upgrade/rollback, independent-client contention, server privileges and restored-release behavior require that environment before deployment.
- Actual browser automation covers the new controls, but it does not replace target-operator usability, source authenticity, full accessibility/screen-reader/mobile or the complete customer journey. The existing app shell and large bundle still need broader release work.
- Source references are operator-entered and unverified. The application does not fetch references, prove consent or turn a recorded inference into a fact. A context revision records a correction, not a new independent enquiry/person identity.
- Import-row mapping, transactional resumable commit, contact correction, duplicate/shared-contact/repeated-enquiry resolution and automatic freshness/re-analysis remain later L2 work. Some API views still load an entire workspace and require pagination/load evidence; no measured scale promise is made here.
- Business criteria are descriptive; fit/priority scoring and held-out usefulness/grounding evaluations remain L3. Full composer/inbox/follow-up/outcome work and account/operations acceptance remain later gates.
- A saved context change cannot recall an already-authorized provider operation. Previewing again preserves prior copy; the human must review it against corrected facts.
- The requested modern interactive landing page remains specified in L4-07/L5-07, with publication gated separately.
