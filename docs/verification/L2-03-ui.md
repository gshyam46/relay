# L2-03 React identity review verification

Date: 2026-09-12. Product: **AI Lead Intelligence & Outbound Automation**.
Scope: the [recorded identity-resolution contract](../L2-03_IDENTITY_RESOLUTION.md). Evidence below is local automated browser execution and engineer visual inspection with synthetic data. It is not target-operator acceptance, real PostgreSQL proof or live-provider threading validation.

## Implemented owner journey

Valid unresolved duplicate rows expose Review duplicate, including late HELD rows after the original selected import finishes. The comparison dialog presents the source row, exact typed enquiry, unchanged raw cells, current candidate enquiry facts and contact-policy warnings. No decision, target or separate-enquiry classification is preselected. Existing candidates are displayed ten per page, from the bounded server list of fifty, with actual shown/total and truncation text. In-file candidates disclose their twenty-row display limit. A candidate is described as a match requiring review, not a verified person.

Link to the same enquiry requires an eligible exact contact-pair candidate. Different, additional or conflicting historical contacts show a reason that linking is unavailable. A separate enquiry requires REPEATED_ENQUIRY, SHARED_CONTACT or DISTINCT_ENQUIRY and creates from the reviewed source. Both choices require a reason and explicit review confirmation; the final button states whether it will link source or create an enquiry. Source and candidate restrictions remain visible and cannot be cleared through this workflow.

Stale comparisons preserve the selected decision, target and reason while blocking Save until the comparison is refreshed and confirmed again. On an uncertain response, the dialog reads saved resolution history first. A recorded result is displayed without another write. If no result is found, only an explicit retry of the identical command is offered. Failure to read history requires another history check before retry. Closing the dialog does not promise to undo a request already admitted by the server.

Rows and decision history show the saved classification, reason, actor/time and resulting enquiry link. Resolution counts remain distinct from original selected-import progress. A resolved HELD row retains its original held outcome and frozen selection. In-file groups can create the first enquiry explicitly and then link another source to it.

The lead Enquiry view now includes Imported source history, covering ordinary imported sources, sources used by identity creation and source-only links. It shows recorded mapped/raw values and exact typed facts, with source-row/history links. Attached source facts are explicitly separate from current enquiry facts; linking does not replace facts or current intelligence. Source links open the relevant import page and row. Shared enquiry summaries label imported provenance as CSV source instead of repeatedly printing raw identifiers; manual source text and persisted provenance are preserved.

The server remains authoritative for permissions, exact contact matching, review tokens, durable outcomes, source validation and restrictions.

No new dependency, package script, provider integration or database layer was added by this UI slice.

## Remaining acceptance and limits

Required human QA is open: a representative operator explains same versus repeated/shared enquiries; links conflicting source without mistaking it for current truth; recognizes suppression; creates the first enquiry in an in-file group; recovers an uncertain decision; and navigates source/history links without developer help. Include keyboard-only use, focus after dialog/error transitions, screen reader, zoom, mobile and long multilingual facts. Desktop automated execution and engineer inspection do not certify these outcomes.

The explicit existing Playwright package is not a dependency-locked portable CI browser setup. Full accessibility scanning, broader application mobile navigation and initial-bundle optimization remain product work. Candidate/policy safety limits intentionally leave exceptional reviews unavailable; the operator needs the documented operational path rather than a client bypass. Exact identity/provenance/transaction and ambiguous-reply behavior are separately verified by backend/root checks. Real PostgreSQL concurrency/upgrade/restore, provider threading and customer acceptance remain external gates. Contact correction, fact merging, full source pagination and ambiguous reply reassignment are not completed by this bounded identity UI.
