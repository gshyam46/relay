# L3-03 AI admission and usage verification

Date: 2026-09-12. Implementation evidence for [L3-03](../L3-03_ANALYSIS_JOBS.md) and ADR-020. All provider responses here are injected synthetic envelopes. No hosted model, external provider or customer dataset was contacted.

## Implemented boundary

Application factories configure an immutable gateway per root database. Async-local invocation contexts bind synthesis to a domain-event fence and reply classification to a receipt fence. The gateway validates the actual adapter request before admission. The workspace transaction checks scope, active lead, current origin state/fence/lease, job cancellation and captured generation identity. It commits one unique permit before I/O. Replaying the same purpose and origin fence cannot obtain a second permit.

Default controls are 100 admissions per captured UTC day and two logical in-flight requests. Only a current workspace owner can revise pause, bounded limits and optional exact provider/model rates. Revision history preserves the actor and reason. Rate configuration is explicit USD per million input/output tokens, accepts at most six fractional digits, and supplies no prices by default.

Every admitted attempt continues to count after rejection, cancellation, invalid output, timeout or lost observation. An elapsed 15-second logical deadline can close an unobserved slot as UNCONFIRMED/RECOVERY_UNKNOWN; this does not claim the remote request stopped. A late, exact authorization-token observation can settle that attempt after event cancellation or fence loss. Conflicting observations cannot rewrite the first recorded result. The budget clock is monotonic: a held admission commits the day it observed, and clock rollback cannot reopen a prior allowance.

The adapter separates bounded telemetry from completion JSON. Validated provider-reported usage survives refused, truncated, tool-bearing and invalid-JSON completion content. Absent, incomplete, inconsistent or malformed counts remain UNKNOWN with null counts; explicit reported zero remains zero. Elapsed milliseconds are client observations, not provider compute time. No prompt, reply, credential, endpoint, raw body or raw error is stored in the usage ledger.

A cost estimate uses the exact owner rate captured at admission and validated input/output tokens. Arithmetic uses integer microUSD; the combined input/output numerator rounds upward once per attempt to the next microUSD. Later rate revisions cannot reprice earlier attempts. Totals separately show the estimated subtotal and unknown-cost attempt count. No rates or no valid token usage means unknown cost, not zero. These are estimates, not invoices or a monetary spending ceiling.

Configured synthesis fingerprints include the requested provider/model and its pipeline, prompt, schema and adapter identity. Root-database descriptor lookup gives transaction-scoped readers the same identity as generation. A separate frozen pipeline_versions manifest binds jobs to snapshot, recommendation, planner and business-fit versions; this job-only manifest does not unnecessarily change the synthesis signature when only a downstream stage version changes. The synthesis pipeline advances to l3.03-extractive-synthesis-v4. A late failure cannot downgrade an already READY or SUPERSEDED synthesis.

Synthesis admission/accounting errors propagate as explicit stage holds instead of becoming reusable READY fallbacks. Reply admission/accounting errors produce UNKNOWN with AI_ADMISSION_UNAVAILABLE and human review. Explicit locally supported opt-out handling precedes model admission and continues while AI is paused. Deterministic stages, existing current artifacts and direct opt-out handling create no model attempt.

## Remaining external evidence

SQLite and injected-adapter behavior does not certify native PostgreSQL concurrency, an actual provider's usage envelope, invoice reconciliation, pricing suitability, realistic throughput or customer benefit. Root records final integrated CI/migration/browser evidence separately. Actual hosted-provider/model QA, native PostgreSQL scenarios and customer pilot acceptance remain explicit external work. A process lost after receiving usage but before committing it leaves the admission visibly unknown; replay cannot reconstruct missing telemetry or refund its daily allowance. Existing receipt retry and event retry policy remain authoritative. The logical in-flight limit cannot establish remote concurrency after a timeout.
