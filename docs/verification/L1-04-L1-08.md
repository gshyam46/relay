## Completed

The [contract](../L1-04_L1-08_DISPATCH.md) was recorded before dependent implementation. This increment adds independent durable contact restrictions, an exact review/decision/revocation flow, captured provider dispatch and a short atomic authorization transaction before external I/O.

An opt-out blocks matching queued work and later dispatch across directly shared contact identities. A valid SendGrid unsubscribe/complaint/hard bounce restricts its authenticated recipient even without a surviving action reference. Ordinary replies and delivery cannot restore contact eligibility. Compatible inbound retries repair restriction effects before ancillary processing.

Every supported SEND requires the current reviewed recipient/sender/message revision. Edits create a new preview; decisions use its expected_revision_id. Revocation holds an approved action or a known-safe queued retry, even when invalid current sender/recipient prevents preparing a replacement preview. Completed/in-flight work cannot be reopened by approval. Legacy approvals have no authority over a newly invented envelope.

The workspace gate commits STARTED attempt and EXECUTING action before calling the provider, preventing competing local dispatch calls. The adapter uses captured recipient, sender/configuration and exact text; it never rereads mutable lead/settings. Unknown transport/server outcomes remain held without automatic resend. Early delivery callbacks cannot be overwritten by later acceptance/message persistence.

The React review dialog is shared by lead detail and outbound. Batch review displays one action at a time. Editing requires Update preview before Approve; stale decisions require refresh. Email settings accepts SendGrid event/parse verification public keys. Public/auth marketing routing is unchanged; the requested landing page remains planned in [LANDING_PAGE](../LANDING_PAGE.md).

## Known limits and human QA

This is not a launch-ready milestone. L1-04/L1-08 remain [~] until the required external/human acceptance is recorded. L1-05 is partially implemented only for pre-provider ownership and uncertainty hold.

- PostgreSQL concurrency, restricted roles and populated upgrade/recovery remain unverified here. The explicit disposable PostgreSQL target and local Docker daemon are unavailable; SQLite/pool doubles do not substitute for real engine behavior.
- L1-05 still needs bounded retry/backoff/deadline, leases/fencing, process-crash reconciliation and an operator recovery path. Uncertain actions currently remain held; 429 retries lack the required budget/backoff.
- L1-06 still needs due-time enforcement and normal scheduler/follow-up advancement. A future scheduled timestamp is not yet a reliable send-time gate.
- L1-07 still needs durable receipt/processing separation, exact attempt correlation and complete interrupted/out-of-order callback repair. This slice's restriction replay and message ordering cover narrower cases.
- Restriction cancellation scans one workspace's leads; production-shaped load, lock latency and import/identity scale require measurement. No graph identity merge or automatic re-consent exists.
- Real signed event/parse delivery, provider acceptance/delivery/reply/opt-out, key rotation and exact received content must be demonstrated with an authorized test recipient. Configuration alone is not channel verification.
- Human/browser QA: open each review, verify recipient/sender/provider/text, edit-preview-approve, stale preview after another change, revoke a pending retry, opt-out a direct duplicate, inspect hold reasons, and confirm keyboard/mobile use. Typecheck/build and API tests do not replace this walkthrough.
- Full manual/reply/new-message composer, business context, customer value evaluation and the landing-page funnel remain their documented L2-L6 work.
