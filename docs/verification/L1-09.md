# L1-09 bounded AI grounding and message claims

Product: **AI Lead Intelligence & Outbound Automation**.
Date: 2026-09-11.
Owner: AI implementation agent; integrating owner maintains shared specifications and task status.
Scope: implemented and automatically verified safety slice; human product QA and L3 semantic/usefulness evaluation remain pending.

## Decision and scope

The configured model previously returned arbitrary summary/reason text and received every input evidence ID automatically. A name-only record could therefore appear to substantiate an invented budget. Recommendation personalization and planning rationale had equivalent free-text paths.

The bounded L1 fix accepts exact recorded fact selections and lets the application render them. It does not attempt to prove arbitrary prose with another model or a keyword filter. Free-form configured-model recommendation and planning are temporarily held in a visible deterministic safety mode until L3 has business context, claim validation and an evaluation gate. This follows [ADR-008](../DECISIONS.md#adr-008-business-context-and-evidence-grounded-intelligence).

No schema migration, real model request, customer send, provider configuration or deployment was performed. Independent review identified default-agent, workspace-sign-off and planner-lineage bypasses in the first implementation; these were fixed before handoff and reproduced as regressions.

## Implemented contracts

| Boundary | Implemented behavior |
| --- | --- |
| Default and configured synthesis input | Requires current READY snapshot, matching workspace/lead/snapshot ownership, supported claim fields, exact claim-to-evidence field/value support, nonempty usable evidence, and bounded input sizes. Invalid input fails before provider invocation with a generic review error; no foreign values appear in errors. |
| Source uncertainty | Changed current identity/contact values, conflicting field values, LOW confidence, or existing OPTED_OUT/SUPPRESSED status produce source-review fallback without a model call. Research values are recorded evidence requiring review, not verified world facts. |
| Configured model output | Exactly selected_claims, each with field, value and evidence_refs. At most eight selections, one per field, copied from a single supporting input finding. Reject invented values, unknown keys, unsupported references, duplicate fields/references and malformed collections. |
| Synthesis rendering | Application-generated summary quotes selected source values and labels them RECORDED_VALUE. Each summary claim retains its own supporting references; summary references contain only selected claims. Business fit, budget, buying intent and contact permission remain unassessed. |
| Assessment references | Qualification/recommendation references identify the validated records used for deterministic completeness/review assessment. They are not citations supporting arbitrary model prose. |
| Fallback provenance | Summary text visibly labels deterministic fallback; existing summary JSON persists generation.mode, generation.reason and grounding_version. Rejected output or provider failure produces NEEDS_REVIEW and REVIEW_LEAD_INTELLIGENCE, without echoing raw provider errors. |
| Recommendation | Default and configured agents use app-owned deterministic assessment and exact matching snapshot facts; foreign/missing evidence and signal references fail closed. priority.generation records DETERMINISTIC_EXTRACTIVE by default and DETERMINISTIC_SAFETY for a configured model. No model call or generated personalization/reason prose is accepted. |
| Plan | Default and configured agents require trusted lead/snapshot context, validate recommendation workspace/lead/snapshot and supporting references, and use deterministic title/rationale, existing app-owned policy and approval, and a non-executable plan. execution_contract.generation records DETERMINISTIC_EXTRACTIVE by default and DETERMINISTIC_SAFETY for a configured model. No provider call. |
| Reply classification | Existing explicit local opt-out patterns win before provider invocation; instruction-shaped input escalates in default and configured modes. Model output is limited to category, confidence and an exact source excerpt. Other fields/unsupported excerpts, uncertainty, disagreement or provider failure become UNKNOWN/LOW and a human-review next step. Possible model opt-outs receive conservative restriction handling. Explanations/next-step text are app-owned; provenance persists inside existing classification payload. |
| Draft composition | Neutral first-name greeting and invitation. Source type, company, or a reply category never establish enquiry, representation, a substantive answer, callback availability, a booking or direct reply routing. Malformed/instruction-shaped first-name identity is omitted. Arbitrary workspace names are not interpolated into a sign-off; a string labeled organization name can itself contain a promise. Existing restricted status or OPT_OUT reply refuses composition. |
| Router defaults | Default subject is neutral; missing message no longer substitutes internal rationale/reason. Sandbox voice explicitly reports no actual call/customer response. Live voice records request acceptance with connection/spoken content unconfirmed. Explicit human-authored message/subject remains subject to the existing review path. |

Planner invocation adds required trusted lead and snapshot context; NextBestActionService resolves these from the current recommendation input before invoking either planner. Missing/wrong context or unsupported recommendation lineage fails the run.

Pipeline versions changed to l1.09-extractive-synthesis-v2, l1.09-bounded-recommendation-v2 and l1.09-bounded-plan-v2. Current synthesis/recommendation/plan lookups no longer reuse the previous pipeline results. Historical records remain visible; existing queued actions and previously approved copy are not automatically revoked or rewritten. L1-08 must bind/invalidate their reviewed revisions before customer use.

## Limits and remaining work

- Exact-source attribution establishes what a record says, not whether that record is true. Instruction-pattern filtering only catches explicit shapes; it is not a comprehensive injection or multilingual semantic defense. Source material remains quoted data and cannot become tool calls or app policy.
- Freshness checks compare the current snapshot scope and present identity/contact fields. Business-profile versions, age-based expiry, richer attributes, contradiction resolution and business qualification remain L2/L3.
- Default and configured agents now share evidence ownership/support checks and app-owned rendering. Their deterministic assessment still concerns foundation readiness, not validated business fit. The bounded model path is intentionally less expressive than free-form prose.
- A model-supported excerpt does not prove its reply interpretation. Deterministic agreement is a conservative guard; ambiguous cases escalate. Local pattern false positives/negation/quoted text and multilingual opt-out coverage require L3 held-out evaluation. A conservative model opt-out can require later operator correction.
- No live LLM format/quality, cost/latency, browser review, real sender/reply routing, or customer usefulness was measured. Automatic model recommendation/planning calls are disabled in this slice.
- Composer neutrality is a safety fallback, not a completed reply experience. L4 still requires an operator to answer the actual question using reviewed business facts and the original conversation.
- Composer checks do not replace dispatch-time contact restrictions, immutable approval, queued-action cancellation, idempotent execution or verified webhooks. Those remain their own L1 blockers.
