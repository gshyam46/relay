## Completed

Owners can review and correct current name/email/phone/company, compare duplicate contacts and retained restrictions, save an exact reasoned revision, inspect per-field source/history, and archive or restore one enquiry. The directory has supported source/status filters, Current/Archived/All views, server pagination and explicit cross-page export selection. CSV includes contact/archive/revision, six typed enquiry facts, exact budget strings and canonical source JSON.

Corrections preserve original import/enquiry sources and carry applicable old restrictions at their original channel scope. They stop queued actions/workflows and cancel automatic no-response tasks; archive cancels all open follow-ups. Restore restarts nothing. Monotonic data revisions prevent edit-back and archive/restore from making old analysis or approvals current again. Actual inbound messages and authorized provider/delivery facts remain readable and recoverable.

Manual lead creation now commits lead, LeadCreated and audit together and rechecks owner inside the write gate. Authenticated data writes/export derive workspace and actor from the session and recheck current ownership. Exact late provider restrictions can retain their corrected-enquiry association only with immutable send/execution/revision/recipient proof.

The [contract](../L2-04_DATA_MANAGEMENT.md), ADR-016 and module ownership were recorded before source changes. Root integrated shared API, migration registry, logging, CSV helpers, tests and specifications; separate backend, safety and UI owners supplied focused implementation and evidence.

## Contracts changed

GET /api/leads/:id/data supplies current data and paged immutable history. Owner POST data/preview and PUT data require explicit phone interpretation, exact expected revision, reviewed token and reason. POST archive requires the displayed revision, target archive state and reason. Identical accepted retries return the original applied result; UI refreshes authoritative current data separately.

GET /api/leads/directory returns a bounded keyset page; existing GET /api/leads defaults to current records for work pickers. Dashboard and attention exclude archived work and report archive count separately. POST /api/leads/export accepts 1..1000 explicit unique owned IDs and returns leads-export.csv, X-Export-Record-Count, no-store and nosniff. There is no implicit all-record export or partial selection.

Lead.data_revision starts at 0; archived_at is independent of lifecycle/contact status. LeadDataChange stores scoped before/after/provenance, reason, actor, expected/new revision and safety effects. Unchanged revision-0 artifact fingerprints stay compatible.

Correction review scans at most 5000 duplicate candidates and 10000 relevant policy records. Total open actions/workflows/follow-ups must fit the shared 10000-work limit; preserved human tasks count toward availability but not cancellation effects. Pending mandatory receipt policy disables correction. Policy summaries include readable reason/channel pairs. Candidate display is capped at 50 and discloses truncation.

Stored before/after snapshots are capped at 512 KiB each and effects at 1 MiB; public carried IDs are capped at 100 with counts. History defaults to 20 changes, maximum 50, and materializes at most 8 MiB with continuation. Directory defaults to 50 records, maximum 100; large display fields are marked as truncated.

Export preflights UTF-8 identity/source and latest enquiry sizes before reading full values, limits each current data snapshot to 512 KiB and enquiry snapshot to 32 KiB, and retains a final 8 MiB escaped CSV limit. Unrelated source metadata is not loaded. Human spreadsheet display uses visible text labels for formula/control/Unicode/numeric-sensitive strings; exact contact/enquiry JSON remains intact. This is an operational export, not a tenant backup or restore format. Format/risk references are recorded in the contract.

## Known issues

- Real PostgreSQL independent processes, populated upgrade/restore and deployed roles remain unverified here. The 37 skips are explicit evidence gaps.
- Actual authenticated provider events, controlled-mailbox send/reply behavior and target-operator acceptance remain open.
- An uncorrelated reply to an old corrected address has no reliable thread-to-enquiry association in this slice; later inbox/thread assignment must handle it.
- Conservative restriction retention has no verified-address exception or evidenced resubscription command. Correction and restore never clear restrictions.
- Export is not a full tenant portability/deletion or restore implementation; Excel/LibreOffice open-save-reopen behavior still needs human acceptance.
- Existing client bundle-size warning remains. Desktop browser automation and engineer screenshot inspection do not establish mobile, screen-reader or first-time operator usability.
