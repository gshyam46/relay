## Implemented workflow

The owner Email setup panel separates saved local configuration, provider verification, routing and workspace sending controls. Sandbox is explicitly simulated. Supported SendGrid setup remains unverified and live-held even when every local field is present. Unsupported live provider choices are disabled; existing unsupported configuration remains visible until an explicit supported mode change. Other channel panels only permit an explicit Sandbox save and do not expose retained credentials.

Full Email saves send only the six editable values, a captured revision/token, a unique request key and an owner reason. API-key masks keep the existing secret, replacement input changes it and an empty field explicitly clears it. Public-key and mailbox validation remain server-authoritative. Public history contains masked configuration summaries, actor, time, operation, reason and before/after revisions.

Initial loading and refresh are read-only. Provisioning and rotation require distinct explicit commands against saved settings, with a reason. URLs are rendered exactly as returned by the server. Rotation explains that old signed aliases remain valid and does not claim to revoke signing keys. Missing, ambiguous or corrupt setup has an actionable hold rather than a ready badge.

Conflicts retain the draft and require an explicit choice to use the latest reviewed revision or replace the draft. An interrupted mutation retains its exact request in page memory, with GET request lookup and same-command retry. GET confirmation wins over a later failed mutation response. Completion, missing-result, error and refresh callbacks remain bound to their captured request identity; a delayed lookup for an older request cannot clear a newer pending command or replace its draft. Newer revisions or configuration drift are not silently adopted after an accepted save. Secret drafts are not persisted to browser storage; the panel explains that reloading closes the draft, while saved configuration and history remain available.

Exact outbound review displays the captured Email Reply-To or its explicit absence. No provider probe, live test send, provider-verification checkbox, approval or dispatch was added to setup.
