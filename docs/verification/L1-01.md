# L1-01 - Disposable test targets and owned cleanup

Product: **AI Lead Intelligence & Outbound Automation**
Date: 2026-09-11
Status: implementation and synthetic checks complete; real PostgreSQL concurrency/abort demonstration remains pending.

## Completed

- The normal test command launches Node tests with an allowlist of operating-system variables and explicit test configuration. Inherited database URLs, PostgreSQL opt-ins, provider credentials, proxies, and Node preloads are not forwarded to the test child.
- E2E refuses an inherited application database URL, production/staging mode, provider configuration, or file database override before starting the server. Its only database is fresh SQLite in memory; the automatic worker is disabled and test controls are explicitly enabled.
- Workflow verification accepts only a loopback HTTP origin and verifies an explicit isolated E2E capability before any workflow mutation or readiness check. Ordinary development/customer servers and redirects are refused. Sandbox completion uses scoped fixture callbacks with the automatic worker disabled; real-provider configuration is refused, while synthetic sandbox credentials still exercise masking.
- PostgreSQL testing requires both an explicit TEST_DATABASE_URL and TEST_DATABASE_DISPOSABLE=1 acknowledgment. DATABASE_URL is never a fallback and a matching application host/port/database is refused even with different credentials. URL query/fragment overrides are refused; TEST_DATABASE_SSL selects enable/disable independently of application TLS settings.
- Every PostgreSQL fixture receives a random run namespace. A file fixture's schema remains stable across restarts within that run and differs in concurrent or later runs. Adapter-specific tests activate only with the runner's namespace context.
- Normal-run cleanup selects and validates only schemas under that exact run namespace. It cannot delete public, legacy broad-prefix orphans, another run's schemas, or malformed identifiers.
- Cleanup waits for normal child process close. An interrupted run deliberately skips cleanup because test descendants may still be terminating. Its namespace is printed for later inspection; subsequent runs never sweep that orphan namespace. Startup/cleanup failures return a failing exit status, with connection error details redacted.
- API fixtures and smoke verification receive explicit test configuration. startClient accepts a config override for production-shaped authorization tests and exposes in-process services for synthetic fixture setup.

## Remaining limits and human QA

1. Supply a dedicated disposable PostgreSQL database through protected environment values, with TEST_DATABASE_DISPOSABLE=1. Verify the redacted printed host/database and run prefix before the run. Acknowledgment and target comparison cannot prove that a database contains no customer data, or detect every alternate hostname for the same server.
2. Run two full PostgreSQL suites concurrently against that disposable database; verify one run's cleanup leaves the other's schemas intact. Abort one, confirm only its namespace may remain, and inspect it only after all its test processes have stopped. Do not use broad-prefix cleanup or customer staging/production targets.
3. Human QA: inspect the local target/refusal messages and demonstrate normal E2E startup/shutdown. Automated startup, complete HTTP workflow and owned-child shutdown passed as recorded above; a human/browser pass remains pending. The database is intentionally lost when the E2E child exits; no persistent file is deleted by that launcher.
4. The current PostgreSQL adapter's TLS verification limitation belongs to L1-10. This harness does not change production TLS, migration privileges, provider behavior, or application execution safety.
5. Child environment isolation is not an operating-system sandbox. A Node preload supplied to the outer Node process runs before any script can inspect it; do not launch tooling with untrusted NODE_OPTIONS. The safe wrapper does not forward it into its test child.
